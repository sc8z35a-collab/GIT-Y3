# JSound Engin 1.6 — ゼロ・ジャンク予測レンダーファーム × KIWAMI MASTER 16

1.5 までの物理音響合成（2D-FDTD、3OA、AudioWorklet）はそのまま使っています。1.6 では「**いつ鳴らすか**」と「**どの再生機器で聴くか**」の2点を作り直しました。検証は `npm run test:jsound16`（16項目すべて合格）です。

## 1. ゼロ・ジャンク予測レンダーファーム (`RenderFarm16.ts` / `JSoundRenderFarm.ts` / `JSoundRenderWorker.ts`)

**課題**：1.5 で測ると、Ultra 品質の「ポン！」1回ぶんの物理合成（2D-FDTD の激突音、太鼓、りん、鈴…）に 450〜650ms かかっていました。しかもそれを、手が見える**その瞬間のフレーム**にメインスレッドで計算していたため、一番盛り上がる場面で画面が止まり、音も遅れていました。

**1.6 の解決**：

- タイミングが大事な音をすべて、送り先に渡せる `RenderJob`（27種類）に変換し、Web Worker のプールで**先に**計算します。
  - **決めた瞬間に先読み**：プレイヤーが手を選んだ時点で勝敗はもう決まっています。そこですぐ、その結果の音を優先度「高」で計算し始めます。
  - **次のラウンドの9通りを裏で準備**：「自分の手3通り × 相手の手3通り」の主な音を、優先度「低」で空き時間に計算しておきます。
- 優先度は2段階で、同じ音の重複計算はまとめます。計算済みの音は最大72個まで取っておきます。
- 手が見えるフレームでやることは、計算済みの波形を AudioBuffer にコピーするだけです。DSP 計算は0です。
- Worker が使えない環境では、自動でメインスレッド合成に切り替えます（下の負荷ガバナー付き）。
- POCO F7 ではワーカーを3本にし、Cortex-A720 側で動かします。端末判定の `renderWorkers` で本数が決まります。

## 2. 遅延を補正した予約再生

音は、画面に手が見える時刻に合わせて**オーディオ側の時計でサンプル単位で予約**して鳴らします。`getOutputTimestamp()` で時計の対応をとり、出力遅延（Bluetooth イヤホンなら約200ms）と画面表示までの遅延（1.5フレーム）を補正するので、**手が見えた瞬間に音が耳に届きます**（[KIWAMI MOBILE CORE](KIWAMI_MOBILE_CORE_1_0.md) §3）。

同じ激突音の波形からバイブのパターンも作り、同じ瞬間に震わせます（同 §4）。

## 3. KIWAMI MASTER 16 — オーディオスレッドで動くマスタリング (`QuantumMaster16.ts`)

1つのクラス `JSound16MasterKernel` が、Node（テスト）とブラウザの AudioWorklet で**ビット単位で同じ結果**を出します。ワークレットのコードはこのクラス自体を `toString()` して生成するので、2つがずれることはありません（ずれ 0、生成コード 22.7KB）。

信号は次の順に処理します。

1. ISO 226 等ラウドネス補正、8ch Hadamard FDN（空気感の残響）、13弦共鳴弦バンク（1.5 から継続）
2. **NEW チェビシェフ仮想低音**：低域を取り出して音量をそろえ、T2/T3/T4 多項式（$T_k(\cos\theta)=\cos k\theta$）で2〜4倍音を作ります。純音から余計な歪み（相互変調）を出さずに倍音だけを作れます。150Hz より下が出ないスマホのスピーカーでも、太鼓の重さと音程が伝わります（60Hz の基音 → 120/180/240Hz の倍音が基音比 −4.4dB）。
3. **NEW スピーカー保護ハイパス**：再生機器ごとに設定します。スマホでは 150Hz で、小さなスピーカーでは鳴らせない 60Hz を −16dB 落とし、無理な振動を防ぎます。
4. **NEW 3バンド LR4 マルチバンド・ダイナミクス**：ゲインを変えなければ、3つの帯域を足すと元の音と振幅が完全に一致します（全域通過になる。20Hz〜20kHz での誤差 0.00000dB）。
5. **NEW トゥルーピーク・リミッター**
   - デジタルのサンプルとサンプルの間に生じるピークを、4倍オーバーサンプリングのFIRフィルター（97タップ、Kaiser β=7.5）で検出します。誤差は 0.021dB で、1.5 の Catmull-Rom 方式（1.07dB）の約50分の1です。
   - 先読み区間の最小ゲインを O(1) で求め、なめらかに戻したあと移動平均でゲインを下げます。「出力するサンプルに必要なゲイン以下になる」ことが数学的に保証されるので、最後の強制クリップ（音を割る処理）が要りません。
   - **+18.1dBFS を入れても出力は −1.000dBFS、強制クリップ 0回**。別の16倍精度で測ったトゥルーピークも −0.832dBTP です。
   - 天井より小さい音には一切手を加えません（遅延 1.52ms のみ）。歪み（THD+N）は 1.5 比で 80Hz 1.10%→0.436%、1kHz 0.59%→0.000% に下がりました。
6. **NEW ITU-R BS.1770-4 ラウドネス計**：K特性の係数を元のアナログ設計から、実際のサンプリング周波数で計算し直しています（ITU の 48kHz 係数との誤差 8.9×10⁻¹⁶）。瞬時（400ms）・短期（3秒）・ゲート付き統合ラウドネス（−70LUFS の絶対ゲートと −10LU の相対ゲート）を測ります。無音が5秒続いても、統合値の変化は −0.07dB に収まります。

処理は8サンプルごとにまとめて行う、左右対称なFIRを使うなどの工夫で軽くしています。Node での計測では実時間の約3〜5%の負荷です。

## 4. 再生機器に合わせた音作り

| 再生機器 | 内容 |
|---|---|
| イヤホン・ヘッドホン | HRTF 立体音響と本物の重低音をそのまま再生 |
| スマホ本体スピーカー | 仮想低音、スピーカー保護、3バンドで音圧を上げて明瞭に。音の広がりは控えめ |
| PCスピーカー | 控えめな仮想低音と 40Hz の保護ハイパス。ステレオ幅はほぼそのまま |

「自動」にしておくと、スマホではスピーカー用、PCではPCスピーカー用になります。スタジオでいつでも切り替えられます。

## 5. 発音数の管理と負荷ガバナー

- **優先度つきの音の入れ替え**：同時に鳴らせる数を超えたら、優先度が一番低く一番古い音を、プチッという音が出ないようにフェードアウトさせて入れ替えます。激突音などの重要な音は消しません。
- **合成負荷ガバナー**：端末で合成にかかった時間を見て、品質を Ultra → Pro → Lite と自動で下げます。速くなったら戻します。
